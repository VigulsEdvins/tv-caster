# Android TV Dedicated Player Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy a dedicated Android TV player app and server-side TV integration for tv-caster, featuring an on-screen TV remote-navigable overlay with season/episode switching, voice acting/translation selection, video quality switching, and speed controls.

**Architecture:** 
1. **Server (`server.py`)**: Provide `/tv` endpoint delivering the TV player, real-time `/api/tv/state` and SSE/polling endpoints for playback synchronization, and API handlers (`/api/tv/change`) to dynamically switch season/episode, translation, quality, or speed without restarting the app. Include ADB auto-wake/launch capabilities when a cast is triggered.
2. **TV Player UI (`templates/tv_player.html` + `static/tv/`)**: 10-foot TV interface designed for TV screens. Supports D-pad remote navigation (UP/DOWN/LEFT/RIGHT/ENTER/BACK/PLAY/PAUSE). Features a sleek auto-hiding overlay bar (top/bottom) with interactive modal pickers for Seasons/Episodes, Voice Translations, Quality, and Speed, plus timeline seeking.
3. **Android TV APK (`android-tv/`)**: Leanback-compatible Android TV application with `LEANBACK_LAUNCHER` intent, hardware acceleration, wake lock (screen on), and full D-pad remote pass-through pointing to the local tv-caster player URL with configurable server IP fallback.
4. **Wireless ADB Deployment & Automation (`tools/tv_deploy.py`)**: Automatic discovery and one-click wireless ADB pairing/installation to `192.168.1.105:5555`, with direct launch verification.

**Tech Stack:** Python 3 (HTTP/SSE server), HTML5 / CSS3 / JavaScript (Hls.js / Video API with TV D-pad navigation), Android SDK / Java / APK packaging tools, ADB.

**Spec:** User requirements from brainstorming: Keep initiating playback from phone/PC; Android TV displays a custom player UI with an overlay bar (bottom or top) allowing selection of season, episode, voice acting, quality, and speed using the TV remote; installed and deployed via Wireless ADB.

## Global Constraints

- Must work reliably with Android TV D-pad remote (key codes: DPAD_UP 19/38, DPAD_DOWN 20/40, DPAD_LEFT 21/37, DPAD_RIGHT 22/39, DPAD_CENTER 23/13, BACK 4/27, PLAY_PAUSE 85/179).
- Must seamlessly support both HLS (.m3u8) and MPEG-TS / MP4 direct streams generated by tv-caster.
- Must preserve backward compatibility with existing phone/desktop web UI at `/`.
- Safe margin / overscan compliance (5% TV safe area).
- Auto-hide controls overlay after 4 seconds of remote inactivity during playback.

## Review Focus

1. **Remote Navigation Traps:** Modal overlays (e.g. season list or audio selector) must trap D-pad focus and dismiss cleanly on `BACK` without quitting the video.
2. **Stream Switching with State Preservation:** Switching audio track, quality, or episode should retain current timestamp where appropriate (or reset to 0 for new episode) without desyncing player state.
3. **Network Reconnection / Offline Handling:** If WiFi drops momentarily or server restarts, the TV app must show a clean reconnecting overlay rather than crashing.
4. **Hardware Acceleration & Codec Performance:** 1080p and 720p streams must use hardware-accelerated decoding in the WebView/player to prevent stutter or frame drops.
5. **Wireless ADB Connection Loss:** If TV IP changes or ADB disconnects on sleep, the deployment tool and server must handle reconnection gracefully.
